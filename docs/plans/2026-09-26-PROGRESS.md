## Decisions (not decidable from the brief alone)

- S1: the red test was the full mock pipeline (validate/run/grade/analyze/report/calibrate)
  on `--scale pilot4`, driven through the cmd_* functions in a temp root. The build_cells
  test was added after and was green on arrival (covered by the same minimal code).
- S1: H3 overthinking is `{"flag": None, "strict_regression": None}` when max or xhigh has
  no data for a class. This also applies to 5-tier-TIERS datasets that happen to lack one
  of those tiers for a class (previously False = "not observed"). calibration.json's
  legacy `overthinking` bool becomes null in that case.
- S1: only `uniform_max` is dropped when max is absent. The other fixed-tier policies are
  the Pareto baselines; a scale without low/high/xhigh is not in scope.
- S1: the `ref_tier = ... else "max"` fallback (~1806) is untouched: it fires only for a
  class with zero graded records, which tier scoping cannot cause.
- S1: `validate` still probes all five TIERS (incl. max) regardless of scale; the brief
  scopes the matrix, not Phase 0.
- S2: `--append-system-prompt-file` is emitted whenever a worker-context path is given,
  independent of `--stripped` (build_claude_cmd treats them as orthogonal).
- S2: the blind grader gets `stripped` but never the worker context: the grader's
  instructions are in its prompt, and handing it the worker's system prompt would add
  producer-side context to a payload that is blind by shape.
- S2: `--stripped/--worker-context` are on `run`, `run-composite` and `grade`
  (`grade` uses only `--stripped`). `validate` probes and the v2 long-context probe
  stay unstripped (brief allows; noted in README).
- S2: a missing `--worker-context` file is a SystemExit before any call; this test
  was green on arrival (run_mode was written in the run-plumbing cycle).
- S2: all run/grade tests fake `invoke_claude` and `detect_cli_version`; no claude
  process was started.
- S3a: red observation before the fix: run_sandboxed returned after 6.27 s (not < 4 s):
  subprocess.run killed only the child, then communicate() waited on the stdout pipe the
  grandchild inherited. The test carries a positive control (grandchild writes a
  `started` file first) so a grandchild that never launched cannot fake a pass.
- S3a: the job is assigned right after Popen (no CREATE_SUSPENDED; Popen does not expose
  the primary thread handle to resume it). Marked `ponytail:` in code with the ceiling.
- S3a: the tree is also killed after a clean exit (job close on Windows, killpg on POSIX),
  so a detached straggler cannot outlive grading. The POSIX branch was not executed here
  (Windows host); it is `start_new_session=True` + `os.killpg(pid, SIGKILL)`.
